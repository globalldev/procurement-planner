# ИИ-система планирования закупок

Импортёр электроинструмента, садовой техники и сантехники из Китая, плечо поставки 4–6 месяцев.
Система по выгрузке ERP отвечает на вопросы закупщика:

- **что** заказать и **сколько** — по каждому SKU, с округлением до кратности партии;
- **на сколько хватит** текущих запасов с учётом заказов в пути;
- **когда** размещать следующий заказ — календарь на 12 месяцев;
- где **риск дефицита** (не успеем довезти) и **избытка** (заморожены деньги);
- что убрать из автозакупки: низкая наценка (< 25%) и мёртвый ассортимент.

**Дашборд:** https://globalldev.github.io/procurement-planner/

Результат — дашборд (`docs/index.html`), Excel для закупщика (`out/plan.xlsx`) и короткая сводка, которую пишет ИИ-агент.

## Как устроено

```
data/inbox/*.zip ──► planner (Python, детерминированный расчёт) ──► out/plan.json, plan.xlsx
                                                                   │
                         prompts/buyer_brief.md ──► claude -p ◄────┘  (ИИ читает расчёт, пишет сводку)
                                                                   │
                                     dashboard/template.html ──► docs/index.html ──► хостинг + Telegram
```

**Разделение ролей.** Числа считает код: прогноз, проекция остатков, даты и объёмы. ИИ (Claude Code) управляет
циклом — принимает данные, запускает расчёт, проверяет результат на здравый смысл, находит аномалии в данных,
объясняет рекомендации и пишет сводку. Так модель не может «придумать» объём заказа, а каждая цифра воспроизводима.

### Логика расчёта
1. **Спрос, а не продажи.** Месяц, к концу которого товар закончился (остаток на 1-е + приходы − продажи ≈ 0),
   не используется для оценки спроса — продажи там занижены. В этих данных таких пар SKU×месяц ~50%.
2. **Прогноз = уровень × сезонность.** Сезонный профиль категории по 5 годам, уточнённый историей SKU;
   уровень — взвешенное среднее за 12 мес. (свежие весят больше); разовые оптовые отгрузки срезаются.
3. **Проекция остатков по дням** на 18 мес.: остаток сейчас + открытые PO на даты прихода − прогноз.
   Просроченные PO до 60 дней считаем едущими, старше — не учитываем и показываем к проверке.
4. **Дата заказа** = день, когда остаток упадёт ниже страхового запаса, минус плечо (история SKU → поставщик → норматив, ≤ 180 дн. + 14 дн. таможня).
   Сезонные товары не заказываются с приходом в мёртвый сезон.
5. **Объём** = спрос на 90 дней после прихода + страховой − ожидаемый остаток − что ещё приедет; кратность из истории заказов.
   Страховой запас по ABC (95/90/85%), масштабируется по сезону.
6. **Проверка прогноза на истории** (бэктест на прошлом годе): WAPE по кварталу 61% против 97% у «среднего за 12 мес».

Все параметры — в `config.toml`.

## Запуск

```bash
pip install -r requirements.txt
python -m planner all           # расчёт + ИИ-сводка + дашборд + публикация
python -m planner run           # только расчёт и дашборд
python -m planner sku SKU-197B08
```

Новая выгрузка: положить zip в `data/inbox/` → `python -m planner all`. Дашборд покажет, что изменилось с прошлого запуска.
Ежедневно: `powershell -File scripts/install_schedule.ps1 -At 07:00` (Планировщик Windows).
Демо «выгрузка через неделю»: `python scripts/demo_next_drop.py 2026-08-20`.

## Claude Code
- `CLAUDE.md` — роль агента, структура, правила интерпретации данных, чек-лист проверки результата.
- `.claude/skills/procurement-run` — полный цикл с проверкой здравого смысла (`/procurement-run`).
- `.claude/skills/sku-explain` — разбор рекомендации по товару (`/sku-explain SKU-…`).
- `.claude/skills/what-if` — сценарии: «что если поднять уровень сервиса / изменить цикл».
- `prompts/buyer_brief.md` — промпт ИИ-сводки; запускается headless через `claude -p` без инструментов,
  крупные числа сводки сверяются с расчётом автоматически.
