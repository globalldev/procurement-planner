# Пересчёт плана закупок

1. **Данные.** Если пользователь приложил zip/CSV — положи в `data/inbox/` (zip) или замени файлы в `data/raw/`.
   Проверь, что в выгрузке есть все 6 таблиц (`sku_dim`, `sales_monthly`, `stock_monthly`, `purchase_orders`, `receipts`, `supplier_dim`).
2. **Расчёт.** `python -m planner run`. Если упал — читай traceback, чини причину (формат даты, новая колонка), не обходи.
3. **Проверка здравого смысла** (не пропускать):
   - открой `out/plan.json` → `kpi` и `diff`; резкие скачки (> 30%) объясни по данным;
   - топ-5 «заказать сейчас» по объёму и топ-5 дефицитов: `python -m planner sku <id>`, сверь логику из `explain`;
   - сезонность: позиции `space_heaters` с приходом после декабря и `string_trimmers`/`trimmer_blades_accessories` с приходом после мая — пометь как риск «придёт после сезона»;
   - `data_quality` — новые проблемы данных.
4. **Сводка.** `python -m planner brief` (Claude пишет сводку по `out/ai_context.json`, числа только из расчёта).
   Если команда ответила «сводка ИИ отклонена» — в тексте были числа, коды или даты не из расчёта: на дашборде осталась
   автосводка, отклонённый текст лежит в `out/ai_brief_rejected.md`. Запусти `python -m planner brief` ещё раз; если отклонена снова —
   оставь автосводку и скажи об этом пользователю.
5. **Публикация.** `python -m planner publish` — коммит `docs/` в GitHub (Pages обновится за 1–2 мин) + уведомление в Telegram, если включено.
6. **Ответ пользователю:** 3–5 строк — сколько заказать сейчас, главный риск, что изменилось, ссылка на дашборд и путь к `out/plan.xlsx`.
